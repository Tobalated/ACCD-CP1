Pattern, Rhythm & Movement — p5.js Documentation

By: Toba Oni

Project Overview

This project explores pattern, rhythm, color variation, and complex movement using p5.js. The final visual is a dynamic grid where each tile reacts to time, noise, and spatial position, creating a rhythmic composition that shifts in color, form, and motion across the entire window.

The goals were to:

  • Fill the window with a visual pattern using tiling and symmetry.
  • Use HSB color mode to show variations in hue, saturation, and brightness.
  • Use loops to generate repeated shapes with variation.
  • Create a sense of rhythm and movement across the grid.
  • Make the movement complex and non-linear using noise and waves.
  • Document problems, solutions, and reflect on the process.

Process: Problems & Solutions

1. Making the grid feel rhythmic, not random

Problem: Early versions felt either too chaotic or too stiff. The tiles moved, but not in a way that felt like part of a single rhythm.

Solution: I introduced a structured grid and normalized coordinates (u, v) centered around the canvas. Using radial distance distCenter and angle angle = atan2(v, u) gave the animation a strong underlying structure that kept everything connected.

2. Balancing symmetry with variation

Problem: Perfect symmetry looked boring. But adding too much randomness destroyed the sense of structure and made the pattern noisy.

Solution: I kept symmetry in the math (using distance and angle from the center) and injected variation using noise() and time-based sine waves. This preserves a clear backbone while letting each tile move slightly differently.

3. Creating complex, non-linear movement without jitter

Problem: Using random() every frame led to jittery, uncomfortable animation. It looked more like static than a deliberate motion.

Solution: I replaced frame-by-frame randomness with Perlin noise() and layered sin()/cos() functions driven by a global time variable t. This produces smooth, curved motion paths that feel non-linear but still rhythmic.

4. Controlling HSB colors

Problem: With HSB it was very easy to create overly bright, neon color combinations that were visually overwhelming.

Solution: I tied hue to the polar angle and time, and mapped saturation and brightness to both distance from the center and the wave value. This created a soft gradient of intensity from the center outward and made the composition more readable.

5. Keeping the whole canvas active

Problem: Some versions concentrated motion in the center while the edges felt dead.

Solution: I used distCenter inside the wave function sin(distCenter * 10 - t * 4 + noiseTerm), so ripples of motion travel across the entire grid. This keeps the full canvas engaged.

Reflection: Most Interesting Problem

One of the most interesting challenges was designing motion that felt complex and non-linear without becoming chaotic or uncomfortable to watch. In early tests, I relied heavily on random() to move tiles independently. While this technically created movement, it looked jittery and disconnected, more like noise than rhythm. When I tried stacking multiple sine waves with different frequencies, the animation became busy and confusing, with too many competing directions and no clear flow.

The breakthrough came when I combined noise() with a limited set of sine and cosine functions, all anchored to a shared time variable t and the polar coordinates of each tile. Noise added smooth, organic variation, while the trigonometric functions provided rhythmic structure. By mapping color and motion to distance and angle, the grid began to feel like it was “breathing” together. Each tile follows its own slightly different path, but the whole composition still reads as a single, coordinated rhythmic system.

TRY Enhancements

For the TRY part of the assignment, I focused on:

  • Animation: All tiles are animated over time, creating continuous movement.
  • Complex, non-linear motion: Layered sin()/cos() functions with noise() produce curved, non-linear paths instead of simple back-and-forth motion.
  • Randomness / noise: I used noise() as a key driver of variation so the motion remains smooth but unpredictable.

I also experimented with adding a textured image overlay and sound using loadImage() and p5.sound. These worked locally but caused some deployment issues on GitHub Pages, so I decided to keep the final online version focused on the visual rhythmic grid. The exploration still helped me understand how external media can be integrated into p5.js sketches.
